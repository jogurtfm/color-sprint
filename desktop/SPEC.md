# Color Sprint HUD — Windows companion

User requested an always-available Windows desktop app connected to the Obsidian plugin's Markdown data. Original visual direction: early-2000s cyber-anime / futuristic visor, concentric rings, cyan technical diagrams, animated ambient terrain, sound feedback. References are inspiration, not assets to copy.

- Electron native windows: full-screen HUD, tray persistence, independent focus / day widgets, pin controls and optional startup.
- Revision 0.2: default to a curved desktop rim. Three small native edge windows (top status, bottom crescent focus hub, curved right task dock) leave no full-screen input surface over the center. Full visor stays optional; Escape/close returns to the rim. Respect primary-monitor work area and display changes. Show the rim without stealing focus.
- App-owned cache, settings and backups default to Windows Local AppData, not the executable's Documents location. Preserve old preview profile files untouched; do not modify antivirus rules or disable protections. A protected-vault write can still require user-managed security approval; read-only remains the default.
- Revision 0.3: explicit local refresh controls and local file/check timestamps, parent-directory watching with 750 ms fallback, refresh after focus/restore/resume, and no claims to force Obsidian cloud synchronization. Keep the full visor on top, remove opaque root/rim fills, and reveal individual edge panels on hover with a brief grace period and fade/slide exit. Provide persistent-rim override and respect Reduce Motion. Never use a full-screen mouse-capturing surface for the desktop rim.
- Revision 0.3.1: dark translucent glass belongs inside each curved panel, not around it. Preserve fully transparent outer canvas and opaque text/control layers; do not lower the whole widget's opacity to create glass. Default interior opacity is 76–84% to restore contrast over bright apps.
- Revision 0.4: apply curved shapes and translucent glass to the full visor too; reduce floating-panel content/glass opacity while idle and restore it on hover or keyboard focus, leaving timers prominent. Add original dashed glowing circuits and bowed perimeter rails, with no pointer interception, no fake telemetry and no new runtime network assets. Pause hidden animations and honor Motion off / Reduce Motion. Replace unexplained read-only Start with an explicit enable-and-start confirmation; forced read-only launches remain locked and cancel/save failure cannot start a timer.
- Revision 0.5: add a curved app-launch dock with ChatGPT, Blender, Notepad++, FL Studio and REAPER presets, bounded standard-location discovery, native icon/monogram fallback and file-picker/custom shortcut management. Keep launcher targets separate from Markdown, validate before launch, reject command/script targets and shortcut arguments, report launch requests rather than running status, and never launch apps in development/test-mode checks. Optional bottom-dock pinning plus a link to Windows taskbar settings supports a user-configured launchbar workflow; do not kill Explorer, change shell/taskbar registry settings or claim a full Windows taskbar replacement. Increase full-visor contrast with 88% default glass, undimmed panel text and a persistent 65–98% slider while preserving floating-widget idle/hover behavior.
- Reuse ../src/model.ts and digest.ts. Vault Markdown stays authoritative. No second task database; settings/reminder deduplication are local app state only.
- Start read-only. Explicit opt-in to task writes. Compare revision before edits, serialize app writes, preserve backups and reject stale actions. Invalid Markdown keeps last good state visibly stale and disables writes. Never mark work complete merely because time expires.
- Do not write live vault progress in development or tests. Test in workspace fixtures only. No outside-workspace installation, login registration, or shortcut writes during this restricted agent session.
- Native reminders run in the main process, deduplicate, respect timezone, quiet hours and mute. Do not send a flood of past reminders on startup. Native delivery depends on Windows settings. No fake telemetry or pretend calendar connection.
- Sandboxed, isolated renderers; no Node renderer access, no remote content, narrow validated IPC. No microphone capture or external account/network calls at runtime.
- Accessible labels, keyboard escape from full-screen, reduced-motion and quiet-mode controls. Flashy ambient motion must not obscure task controls or trap the desktop.
- Deliver a portable Windows build, launch entry point, screenshots and verified tests. Document actual validation and any limitations honestly.
