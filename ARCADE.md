# Arcade feedback and viewport anchoring

Plugin 0.16.1 / HUD 0.15.1. These are presentation-only changes. No scoring rules,
task data, Relay configuration, watch/poll delivery, pairing trust or progress
records are changed. No migration, new network service or audio upload is added.

## Center stability

The Today focus column is portalled outside the dashboard's perspective parents
and anchored to the screen. The ring's center stays at 50vw / 50dvh during task
list and whole-window scrolling. Controls have a bounded scroll area on shorter
screens. The app dock stays at the lower edge. Other tabs retire this portal;
floating widgets and the curved desktop rim keep their existing layouts.

The single GPU compositor now invalidates cached bounds on document/window/nested
scroll, viewport resize, visibility restoration and layout-size changes. Retired
surfaces dirty and clear the frame even with motion disabled. Layout is still
cached between changes, not remeasured on every animation frame. UI masks retain
their exclusion around text and controls. Panels retain the established curves.

## Rank display and effects

The active interface uses clean cyan D/C/B/A/S/SS/SSS typography, not the gold
raster medals from 0.16.0. The desktop rank is integrated beside the win count
inside Daily progress. It never floats over the timer or navigation. Accessible
rank text, points and the Effort profile button remain. Mobile uses the same
readable typographic mark. The generated atlas is retained only as an editable
source asset, not mounted in the interface.

An upward derived rank/point change produces one short rank-up announcement,
fine cyan pulse, a tiny 1px shake and 12 short particle points. There is no celebration on
initial load, identical refresh, a downgrade or switching dates. Nothing awards
extra XP. Animation is a one-shot, not another permanent canvas/frame loop. The
overlay is pointer-transparent. Motion-off / system Reduce Motion uses a static
announcement with no shake or particles. Existing scores remain authoritative.

## Placeholder audio and replacement

Existing sound toggles mute interface cues as well as completion audio. Existing
HUD volume applies. Hover cues are subtle/throttled and omit touch hover. Click
and navigation cues are distinct; rank-up has a short fanfare. Playback is best
effort after the first user gesture (browser/iOS audio unlock), not a background
alarm. No new audio permission is requested. A silent device stays silent.

Replace these source files, keeping their filenames, then rebuild/package:

- `assets/arcade/hover.wav`
- `assets/arcade/click.wav`
- `assets/arcade/transition.wav`
- `assets/arcade/rank-up.wav`
- `assets/arcade/ranks.png` (retained original art; not used by the current live rank UI)

The four original placeholder WAVs are generated by
`node scripts/make-ui-sounds.mjs`. Do not run that helper after replacing them
unless you want to restore the placeholders. The image-generation brief is
`assets/arcade/PROMPT.md`; the selected built-in generated PNG is preserved there
in the project rather than referenced from a private cache.

WAV assets are embedded as data URLs at build time. PC/mobile installation
still uses the same three plugin runtime files; replacing files in a compiled
release folder alone will not change embedded cues. Editable assets live in the
public repository, not the user's vault or reflections.

## Verification boundary

Model, actual-plugin DOM and HUD/GPU tests check rank transitions, mute, reduced
motion, disposal, cached layout and scroll invalidation. Generic browser fixtures
check readable rank marks, a rank-up, centered coordinates at desktop sizes, scroll,
and mobile layout. Native Windows/iPhone rendering and audible/haptic acceptance
remain separate; publishing is not proof of BRAT download or phone sync delivery.
